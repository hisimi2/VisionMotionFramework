## 1. Vision 기능 vs Sequence — 개념 구분

```

│                        VisionMotionFramework                        │
├────────────────────────────────────────────────────────────────────┤
│                                                                    │
│   ┌──────────────────────────────────┐                             │
│   │       VISION 기능 (공통 가능)      │                             │
│   │                                  │                             │
│   │   "카메라로 찍고, 이미지 처리하고,  │                             │
```

## 2. 동일 Vision, 다른 Sequence — 7가지 차이점

### 2.1 기구적 구조 차이 (Mechanical Layout)

```
[Equip1 장비]                  [Equip2 장비]                  [Picker 장비]
    MoveSafeZ                    MoveSafeZ                     MoveJog
        │                            │                            │
    MoveOrigin                  MoveTargetY                  SensorSearch
        │                            │                            │
    MoveTargetPositionXY        MoveTargetX                   MovePickPosition
        │                            │                            │
    MoveTargetPositionZ         AlignStage                       │
        │                            │                            │
      Home                    MoveTargetPositionZ             PickUp
                                  │                            │
                                Home                        MovePlacePosition
```

**같은 "Z-Focus 검사"지만 축 구성, 순서, 개수가 모두 다르다.**

### 2.2 안전 조건 차이 (Interlock & Safety)

```mermaid
graph TD
    subgraph "Equip1"
        A1[MoveDown 명령] --> B1{도어 닫힘?}
        B1 -->|NO| C1[Error: 도어 열림]
        B1 -->|YES| D1{Stage Lock?}
        D1 -->|NO| E1[Error: Stage 미잠금]
        D1 -->|YES| F1[✅ MoveDown 실행]
    end
    
    subgraph "Equip2"
        A2[MoveDown 명령] --> B2{Air Pressure}
        B2 -->|Low| C2[Error: 압력 부족]
        B2 -->|OK| D2[✅ MoveDown 실행<br/>(속도: SLOW)]
    end
    
    subgraph "Picker"
        A3[MoveDown 명령] --> B3{Gripper 상태}
        B3 -->|Open| C3[✅ MoveDown 실행]
        B3 -->|Closed| D3[Error: Gripper 간섭]
    end
```

| 장비 | 사전 체크 조건 | 실패 시 동작 |
|------|---------------|-------------|
| Equip1 | 도어 닫힘 + Stage Lock | Error 정지 |
| Equip2 | Air Pressure | Error 정지 |
| Picker | Gripper Open 확인 | Error 정지 (Gripper 보호) |

### 2.4 Vision 결과 처리 로직 차이

```
                           Vision 결과 (FocusZ = -2.5mm)
                                    │
                                    ▼
                         ┌──────────────────┐
                         │  결과 해석 / 판단  │
                         └──────────────────┘
                                    │
              ┌─────────────────────┼─────────────────────┐
              ▼                     ▼                     ▼
         [Equip1]                [Equip2]              [Picker]
         범위 체크               범위 체크             범위 체크
              │                     │                     │
         ┌────┴────┐          ┌────┴────┐          ┌────┴────┐
         │OK    │NG           │OK    │NG           │OK    │NG
         ▼      ▼             ▼      ▼             ▼      ▼
       저장   재시도         저장   재시도         저장   재시도
       성공  (3회)          성공   (0회)          성공   (1회)
              │                     │                     │
         3회 실패→Skip         NG 즉시→Stop         1회 실패→Retry
```

| 장비 | NG 시 재시도 | 최종 실패 시 | 결과 저장 위치 |
|------|-------------|-------------|---------------|
| Equip1 | 최대 3회 | Skip (다음 점으로) | FocusResult_Equip1 테이블 |
| Equip2 | 없음 (0회) | Stop (장비 정지) | FocusResult_Equip2 테이블 |
| Picker | 1회 | Retry (재시도 후 Error) | PickerResult 테이블 |

```
              │            │            │
```

### 2.6 외부 장치 연동 차이

```
[Equip1]                         [Equip2]
  ┌──────────┐                   ┌──────────┐
  │  Loader  │ ← Handshake →     │ Conveyor │
  └──────────┘                   └──────────┘
       │                              │
       ▼                              ▼
  Vision 실행                    Vision 실행
       │                              │
       ▼                              ▼
  결과 저장 + Loader에게         결과 저장
  완료 신호 (Handshake)
```

| 장비 | Vision 전 연동 | Vision 후 연동 |
|------|---------------|---------------|
| Equip1 | Loader Handshake 필요 | Loader에 완료 신호 |
| Equip2 | Conveyor 정지 확인 | 없음 |
| Picker | Feeder 동기화 필요 | Ejector 신호 |

### 2.7 성능 튜닝 파라미터

```
동일한 "Z축 하강 (MoveZ 100mm)" 동작

      속도 ↑
      │
  100 ├────────── Equip1 (급가속, 긴감속)
      │    ╱╲
   80 ├──╱──╲────
      │ ╱    ╲   ╲
   60 ├╱      ╲   ╲── Equip2 (저속, 짧은감속)
      │        ╲     ╲
   40 ├─────────╲─────╲──── Picker (분할 2회)
      │          ╲     ╲
   20 ├───────────╲─────╲──
      │            ╲     ╲
      └──────────────────────────→ 시간
```

| 장비 | 속도 | 가속 | 감속 | 특이사항 |
|------|------|------|------|---------|
| Equip1 | HIGH | HIGH | LONG | 빠른 사이클 타임 |
| Equip2 | LOW | LOW | SHORT | 진동 민감 (Focus 정밀도) |
| Picker | MED | MED | MED | 2회 분할 이동 (진동 방지) |

## 3. 결론: 프레임워크 vs 장비 코드의 역할

```
┌─────────────────────────────────────────────────────────────────────┐
│                   VisionMotionFramework 생태계                       │
├──────────────────────────┬──────────────────────────────────────────┤
│                          │                                          │
│   🏗️ 프레임워크 (NuGet)   │   🔧 장비 코드 (Template)                 │
│                          │                                          │
│   ┌──────────────────┐   │   ┌──────────────────────────────────┐   │
│   │ NonBlockingTask  │   │   │ MyMoveToStartPositionTask       │   │
│   │   Base           │───┼──→│  (Equip1: SafeZ→Origin→XY→Z)    │   │
│   │  [Task 패턴 제공]  │   │   │  (Equip2: SafeZ→Y→X→Align→Z)  │   │
│   └──────────────────┘   │   └──────────────────────────────────┘   │
│                          │                                          │
│   ┌──────────────────┐   │   ┌──────────────────────────────────┐   │
│   │ SequenceBuilder  │   │   │ MyZFocusSequenceBuilder          │   │
│   │   Base           │───┼──→│  (Task A → Task B → Task C)     │   │
│   │  [조립 패턴 제공]  │   │   │  (Task A → Task D → Task E)     │   │
│   └──────────────────┘   │   └──────────────────────────────────┘   │
│                          │                                          │
│   ┌──────────────────┐   │   ┌──────────────────────────────────┐   │
│   │ ComponentSetup   │   │   │ MyStrategy                      │   │
│   │   Base           │───┼──→│  (CameraIndex=6, 좌표=X:125.3)  │   │
│   │  [설정 패턴 제공]  │   │   │  (CameraIndex=3, 좌표=X:89.1)   │   │
│   └──────────────────┘   │   └──────────────────────────────────┘   │
│                          │                                          │
│   ┌──────────────────┐   │   ┌──────────────────────────────────┐   │
│   │ IDataRepository  │   │   │ (DB 연결 문자열만 다름)            │   │
│   │ [저장 인터페이스]  │───┼──→│                                  │   │
│   └──────────────────┘   │   └──────────────────────────────────┘   │
│                          │                                          │
│   ┌──────────────────┐   │   ┌──────────────────────────────────┐   │
│   │ IVisionProcessor │   │   │ (설정 파라미터만 다름)             │   │
│   │ [Vision 실행 API] │───┼──→│                                  │   │
│   └──────────────────┘   │   └──────────────────────────────────┘   │
│                          │                                          │
│   ┌──────────────────┐   │                                          │
│   │      Mock        │   │   ※ 장비별 DLL로 빌드                     │
│   │ (CMockDataRepo,  │   │   Main APP이 LoadLibrary로 로드          │
│   │  CMockVision)    │   │                                          │
│   └──────────────────┘   │                                          │
│                          │                                          │
│   ❄️ 변경 거의 없음       │   🔄 자주 변경됨                          │
│   (인터페이스 변경 시만)   │   (장비 추가/수정/튜닝 시)                │
├──────────────────────────┴──────────────────────────────────────────┤
│                                                                     │
│   📌 핵심 메시지:                                                   │
│                                                                     │
│   "프레임워크는 '어떻게 구조화할지'의 패턴을 제공한다.                  │
│    장비 코드는 '내 장비가 구체적으로 어떻게 동작할지'를 표현한다.       │
│    하드웨어가 다른데 소프트웨어가 같을 수 없다."                      │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

## 4. 한눈에 보는 비교표

| 항목 | 프레임워크 (NuGet) | 장비 코드 (Template) |
|------|-------------------|---------------------|
| **제공하는 것** | Task/Sequence/Strategy의 **뼈대(틀)** | 구체적인 **움직임과 판단 로직** |
| **변경 이유** | 인터페이스 개선, 버그 수정 | 장비 추가, 구조 변경, 튜닝 |
| **변경 빈도** | ❄️ 거의 없음 (월/년 단위) | 🔄 자주 발생 (일/주 단위) |
| **재사용 범위** | 모든 Equipment 공통 | 해당 Equipment 전용 |
| **테스트 방식** | Mock으로 단위 테스트 | 실제 장비 연결 통합 테스트 |
| **배포 단위** | NuGet 패키지 | VS Template → DLL |
| **한 줄 정의** | "이렇게 만들어라" (How to build) | "이렇게 움직여라" (How to move) |

---

> **요약**: VisionMotionFramework는 **"Sequence를 만드는 방법"** 을 제공합니다.  
> **"어떤 Sequence를 만들지"** 는 장비 개발자가 자기 장비에 맞게 직접 작성해야 합니다.  
> 이것은 프레임워크의 한계가 아니라, **소프트웨어와 하드웨어가 만나는 본질적인 경계**입니다.
